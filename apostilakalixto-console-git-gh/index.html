Console de versionamento

Os comandos que você usa todo dia no terminal, em dois circuitos: o Git, que cuida do histórico local, e o gh, que fala direto com o GitHub.

Comandos Git

Controle de versão local: histórico, ramos e sincronização com o remoto.

  • git init

    Transforma a pasta atual em um repositório Git, criando o diretório .git onde todo o histórico passa a ser guardado.

    git init
git branch -M main
  • git clone

    Baixa um repositório remoto inteiro, com todo o histórico, e já configura o origin apontando para ele.

    git clone https://github.com/usuario/projeto.git
git clone --depth 1 <url>   # só o último commit
  • git status

    Mostra em que ramo você está e quais arquivos foram modificados, adicionados ao stage ou ainda não são rastreados.

    git status
git status -s   # versão curta, uma linha por arquivo
  • git add

    Coloca as alterações no stage, ou seja, marca o que vai entrar no próximo commit.

    git add index.html
git add .        # tudo que mudou
git add -p       # escolher trecho por trecho
  • git commit

    Grava no histórico tudo que está no stage, junto com uma mensagem que explica a mudança.

    git commit -m "adiciona painel de comandos"
git commit --amend   # corrige o commit anterior
  • git branch

    Lista, cria ou apaga ramos — linhas de trabalho paralelas que não interferem na principal.

    git branch                 # lista
git branch feature/login   # cria
git branch -d feature/login   # apaga
  • git switch

    Troca de ramo. Substitui o antigo git checkout para essa função, que era ambíguo demais.

    git switch main
git switch -c feature/api   # cria e já entra
  • git merge

    Junta o histórico de outro ramo no ramo atual, criando um commit de merge quando as duas linhas divergiram.

    git switch main
git merge feature/login
  • git rebase

    Reaplica seus commits sobre outra base, deixando o histórico linear. Evite em ramos que outras pessoas já baixaram.

    git rebase main
git rebase -i HEAD~3   # editar os 3 últimos
  • git pull

    Busca as novidades do remoto e já integra ao ramo atual — é um fetch seguido de merge.

    git pull
git pull --rebase   # integra sem commit de merge
  • git push

    Envia seus commits locais para o repositório remoto.

    git push
git push -u origin main   # define o rastreamento na 1ª vez
  • git log

    Percorre o histórico de commits, do mais recente para o mais antigo.

    git log --oneline --graph --all
  • git diff

    Mostra linha a linha o que mudou entre o que está salvo, o stage e os commits.

    git diff            # ainda fora do stage
git diff --staged   # o que vai no commit
  • git stash

    Guarda temporariamente as alterações em andamento e devolve a pasta limpa, para você trocar de contexto sem commitar pela metade.

    git stash
git stash pop   # devolve o que foi guardado
  • git restore

    Desfaz alterações em arquivos ou tira do stage o que você adicionou por engano.

    git restore index.html
git restore --staged index.html
  • git remote

    Gerencia os endereços remotos do projeto — normalmente o origin.

    git remote -v
git remote add origin <url>
  • git reset

    Move o ponteiro do ramo para outro commit. Com --hard descarta o trabalho não commitado, então use com atenção.

    git reset --soft HEAD~1   # desfaz o commit, mantém as mudanças
git reset --hard HEAD~1   # desfaz tudo

Nenhum comando Git corresponde ao filtro.

Comandos gh

GitHub CLI: pull requests, issues e releases sem sair do terminal.

  • gh auth login

    Autentica a CLI na sua conta do GitHub, pelo navegador ou por token. É o primeiro passo antes de qualquer outro gh.

    gh auth login
gh auth status   # confere quem está logado
  • gh repo create

    Cria um repositório no GitHub direto do terminal, com opção de já enviar o projeto local.

    gh repo create painel-git --public --source=. --push
  • gh repo clone

    Clona usando apenas usuario/repo, sem precisar da URL completa, e já resolve a autenticação.

    gh repo clone cli/cli
  • gh repo fork

    Cria um fork na sua conta e, se quiser, clona e configura o upstream na mesma passada.

    gh repo fork cli/cli --clone
  • gh pr create

    Abre um pull request do ramo atual, pedindo título e descrição de forma interativa.

    gh pr create --base main --title "Painel de comandos" --body "Adiciona o console."
gh pr create --fill   # usa os commits como título e corpo
  • gh pr list

    Lista os pull requests do repositório, com filtros por autor, estado e rótulo.

    gh pr list --state open --author "@me"
  • gh pr checkout

    Baixa o ramo de um pull request pelo número, para você revisar e testar localmente.

    gh pr checkout 42
  • gh pr review

    Aprova, pede alterações ou deixa um comentário de revisão sem abrir o navegador.

    gh pr review 42 --approve
gh pr review 42 --request-changes --body "Falta tratar o erro"
  • gh pr merge

    Faz o merge do pull request escolhendo a estratégia e, se quiser, já apaga o ramo.

    gh pr merge 42 --squash --delete-branch
  • gh issue create

    Abre uma issue com título, corpo, rótulos e responsáveis definidos na própria linha de comando.

    gh issue create --title "Ajustar contraste" --label bug --assignee "@me"
  • gh issue list

    Mostra as issues abertas do repositório, com os mesmos filtros disponíveis na web.

    gh issue list --label "good first issue"
  • gh release create

    Publica uma release a partir de uma tag e anexa os arquivos de distribuição.

    gh release create v1.0.0 ./dist/*.zip --notes "Primeira versão"
  • gh workflow run

    Dispara manualmente um workflow do GitHub Actions e permite passar parâmetros de entrada.

    gh workflow run deploy.yml --ref main
gh run watch   # acompanha a execução ao vivo
  • gh gist create

    Publica um arquivo como gist e devolve o link pronto para compartilhar.

    gh gist create script.py --public
  • gh browse

    Abre no navegador a página do repositório, de um arquivo ou de uma issue específica.

    gh browse
gh browse src/app.js

Nenhum comando gh corresponde ao filtro.
