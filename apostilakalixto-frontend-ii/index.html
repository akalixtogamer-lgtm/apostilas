Fundamentos

Introdução ao JavaScript

Conceito teórico

JavaScript (JS) é uma linguagem de programação de alto nível, interpretada e multiparadigma. Nasceu para dar vida às páginas web: validar formulários, reagir a cliques, atualizar a tela sem recarregar. Hoje vai muito além do navegador.

História rápida

Foi criada em 1995 por Brendan Eich, na Netscape, em apenas 10 dias. O nome "JavaScript" foi marketing (Java estava na moda) — as duas linguagens são diferentes. Em 1997 o padrão foi formalizado como ECMAScript. A virada moderna veio com o ES6 (ES2015), que trouxe let, const, arrow functions, classes e template strings — a base desta apostila.

Analogia

Pense numa página web como um corpo: o HTML é o esqueleto (estrutura), o CSS é a roupa e a aparência (estilo), e o JavaScript é o sistema nervoso (comportamento) — é ele que faz o corpo reagir quando você toca nele.

ECMAScript: o que é?

ECMAScript é a especificação (as regras oficiais) e JavaScript é a implementação dela. Versões importantes: ES5 (2009), ES6/ES2015 (revolução moderna), e lançamentos anuais (ES2016... ES2024). Quando você lê "ES6+", é "do ES2015 em diante".

Como o navegador executa JavaScript

Todo navegador tem um motor (engine) que lê e roda seu código: o Chrome usa o V8, o Firefox o SpiderMonkey, o Safari o JavaScriptCore. O motor lê o código, compila "na hora" (JIT) e executa.

Interpretado vs. Compilado

InterpretadoCompilado
Lê e executa linha a linhaTraduz tudo para máquina antes de rodar
Mais flexível, erros aparecem em execuçãoMais rápido, erros aparecem antes
Ex.: JavaScript (clássico), PythonEx.: C, Rust

Na prática, JS moderno é híbrido: o V8 interpreta e compila JIT as partes "quentes" para ganhar velocidade. Para iniciante: pense em "interpretado".

Onde JavaScript é usado hoje

  • Front-End — interfaces no navegador (React, Vue, Angular, ou JS puro).
  • Back-End — servidores com Node.js (APIs, bancos de dados).
  • Mobile — apps com React Native, Ionic.
  • Desktop — programas com Electron (o VS Code é feito assim!).
  • IA — TensorFlow.js roda modelos no navegador.
  • IoT — dispositivos com Johnny-Five, Espruino.
Empresas que usam JS

Netflix usa Node.js para reduzir o tempo de inicialização do app. A Uber processa eventos em tempo real com Node. O PayPal migrou para Node e dobrou a velocidade de resposta. O LinkedIn reescreveu o back-end mobile em Node. A Meta criou o React, hoje o framework front-end mais usado do mundo.

Primeiro código

ola.js
// Isto é um comentário — o motor ignora esta linha
console.log("Olá, mundo Kalixto! 🎮");

// console.log() imprime no Console do navegador (F12)
let nome = "Wallace";
console.log("Bem-vindo, " + nome);
Olá, mundo Kalixto! 🎮 Bem-vindo, Wallace
Erros comuns

consol.log() (faltou o "e") → "consol is not defined". JavaScript diferencia maiúsculas: Console ≠ console. Esquecer aspas em texto também quebra: console.log(Olá) tenta usar "Olá" como variável.

Boas práticas

Comente o porquê, não o óbvio. Use nomes descritivos. Teste cada trecho no Console antes de seguir.

Exercício resolvido — "Quem sou eu"

Crie variáveis com seu nome, sua profissão e imprima uma frase de apresentação.

solucao.js
let nome = "Wallace";
let papel = "Professor · Programador · Gamer";
console.log(nome + " — " + papel);
Wallace — Professor · Programador · Gamer
Exercícios propostos
  • fácil Imprima 3 hobbies seus, um por linha.
  • fácil Crie a variável ano e imprima "Estamos em 2026".
  • médio Pesquise: cite 3 empresas brasileiras que usam JavaScript.

Configuração de Ambiente

O kit do desenvolvedor Front-End

Para programar você precisa de pouca coisa: um navegador (Chrome) e um editor de código (VS Code). Nada de instalar coisas pesadas no começo.

VS Code

O Visual Studio Code é o editor mais usado no mundo. Gratuito, leve e cheio de extensões. Instale e adicione: Live Server (abre seu HTML no navegador e recarrega sozinho), Prettier (formata o código) e ESLint (aponta erros).

Chrome DevTools & Console

Aperte F12 (ou Ctrl+Shift+I) para abrir as DevTools. A aba Console é onde o JavaScript "fala com você": é onde aparecem os console.log e os erros (em vermelho). Você pode digitar JS direto ali para testar.

Estrutura HTML + CSS + JS

index.html
<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="UTF-8">
  <title>Meu Projeto</title>
  <link rel="stylesheet" href="estilo.css">
</head>
<body>
  <h1>Olá Kalixto</h1>

  <!-- O JS vai no final do body para o HTML carregar antes -->
  <script src="script.js"></script>
</body>
</html>
Boas práticas

Coloque o <script> no final do <body> (ou use defer). Assim o HTML já existe quando o JS tenta manipulá-lo — senão você tenta mexer em elementos que ainda não nasceram.

Erros comuns

Script no <head> sem defer → o JS roda antes do HTML existir e dá null. Caminho errado em src → o arquivo não carrega (confira maiúsculas e a pasta).

Variáveis

Conceito

Uma variável é uma "caixa" com nome onde você guarda um valor para usar depois. Em JS moderno usamos três palavras para declarar: var (antiga), let e const.

Analogia

Variável é como um armário com etiqueta. A etiqueta é o nome (idade), o conteúdo é o valor (25). let = armário que você pode trocar o conteúdo. const = armário lacrado, conteúdo fixo.

variaveis.js
let idade = 25;        // pode mudar depois
idade = 26;           // ok ✅

const PI = 3.14;      // valor fixo
// PI = 3.15;         // ❌ TypeError: Assignment to constant variable

let nome = "Kalixto"; // texto
console.log(nome, idade, PI);
Kalixto 26 3.14

Escopo: onde a variável "existe"

  • Global — declarada fora de tudo, vista em qualquer lugar.
  • Local (de função) — só existe dentro da função.
  • De bloco — let/const só vivem dentro do { } onde nasceram.
escopo.js
if (true) {
  let dentro = "só existo aqui";
  var vazado = "eu escapo do bloco";
}
// console.log(dentro);  // ❌ erro: dentro is not defined
console.log(vazado);     // ⚠️ funciona — var ignora o bloco
eu escapo do bloco

Hoisting

Hoisting é a "elevação": o JS move as declarações para o topo antes de rodar. Com var a variável existe mas vale undefined; com let/const ela fica numa "zona morta temporal" e dá erro se usada antes.

Tabela comparativa

varletconst
EscopoFunçãoBlocoBloco
Pode reatribuir?SimSimNão
Pode redeclarar?Sim ⚠️NãoNão

Recomendado?❌ evite✅ sim✅ preferível
Bug real causado por var

Em um for com setTimeout, var i compartilha a mesma variável e imprime o valor final em todos os callbacks. Com let i, cada volta tem seu próprio i. Esse bug clássico já consumiu horas de muita gente.

Boas práticas

Use const por padrão. Só troque para let quando precisar reatribuir. Nunca use var em código novo.

Exercício resolvido — Troca de valores

Troque o conteúdo de duas variáveis usando uma terceira (ou desestruturação).

troca.js
let a = 1, b = 2;
[a, b] = [b, a];   // jeito moderno (desestruturação)
console.log(a, b); // 2 1
2 1

Template Strings

Conceito

Template strings (ou template literals) usam crases ` ` em vez de aspas. Permitem interpolação (${ }) e texto em múltiplas linhas.

Concatenação antiga vs. moderna

template.js
const nome = "Wallace", idade = 26;

// ❌ jeito antigo: + e " " por todo lado
const v1 = "Olá, " + nome + "! Você tem " + idade + " anos.";

// ✅ template string: limpo e legível
const v2 = `Olá, ${nome}! Você tem ${idade} anos.`;

// múltiplas linhas, sem \n
const card = `
  Aluno: ${nome}
  Idade: ${idade}
  Status: ${idade >= 18 ? "adulto" : "menor"}
`;
console.log(v2);
Olá, Wallace! Você tem 26 anos.
No mundo real

Em sistemas, template strings montam HTML dinâmico, mensagens de e-mail, queries e logs. É a forma padrão de juntar texto com variáveis em JS moderno.

Truque do %

numero % 2 === 0 diz se um número é par. O resto é usado o tempo todo: paginação, alternância de cores em listas (linha par/ímpar), relógios.

Atribuição e Incremento

operadores.js
let saldo = 100;
saldo += 50;  // saldo = saldo + 50 → 150

saldo *= 2;   // 260
saldo /= 4;   // 65

let pontos = 5;
console.log(pontos++); // 5 (usa, depois soma) → pós-incremento

5 6 7
Erro comum

Confundir pré e pós incremento dentro de expressões. Em dúvida, separe: incremente em uma linha e use na outra.

Conversão de Tipos

Implícita vs. Explícita

Implícita (coerção): o JS converte sozinho — às vezes de forma surpreendente. Explícita: você manda converter, com controle total.

conversao.js
// Implícita (cuidado!)
console.log("5" + 3);   // "53"  → vira texto
console.log("5" - 3);   // 2     → vira número
console.log("5" * "2"); // 10

// Explícita (recomendado)
console.log(Number("42"));     // 42
console.log(String(42));       // "42"
console.log(Boolean(0));       // false
console.log(parseInt("10px")); // 10
console.log(parseFloat("3.5kg")); // 3.5
53 2 10 42 42 false 10 3.5

NaN, Infinity e BigInt

  • NaN = "Not a Number". Resultado de contas inválidas: Number("abc").
  • Infinity = divisão por zero: 1/0.
  • BigInt = números acima do limite seguro (2^53), com n no final.
Bug real

Um formulário recebe a idade como texto. Sem converter, "30" + 1 vira "301" em vez de 31. Sempre Number() entradas numéricas vindas de inputs.

Diferença perigosa: == vs ===

== converte os tipos antes de comparar, gerando resultados malucos: 0 == "" → true, null == undefined → true. Use sempre === para evitar bugs silenciosos.

console.log(5 == "5");    // true  — coerção

console.log(0 === false); // false ✅

Estruturas Condicionais

O fluxo de decisão

condição?→ verdadeiro → faz A| falso → faz B
condicionais.js
const idade = 17;

// if / else if / else
if (idade < 12)       console.log("Criança");
else if (idade < 18)  console.log("Adolescente");
else                  console.log("Adulto");

// switch — bom para valores fixos
const dia = 3;
switch (dia) {
  case 1: console.log("Domingo"); break;
  case 2: console.log("Segunda"); break;
  default: console.log("Outro dia");
}

// ternário — if curto em uma linha
const status = idade >= 18 ? "maior" : "menor";
console.log(status);
Adolescente Outro dia menor

Quando usar cada um

UseQuando
if/elseCondições com intervalos ou expressões (idade < 18)
switchComparar 1 variável com vários valores fixos
ternárioEscolha simples entre 2 valores
Erro comum

Esquecer o break no switch → ele "vaza" e executa os próximos cases. Em ternários aninhados demais, vira sopa ilegível — prefira if.

Estruturas de Repetição

Conceito

Loops repetem um bloco de código várias vezes — para não copiar e colar mil vezes.

Analogia

Um loop é como ensinar uma coreografia: você repete o mesmo passo até a contagem terminar. break é parar a música no meio; continue é pular um passo e seguir.

loops.js
// for — quando você sabe quantas vezes
for (let i = 1; i <= 3; i++) console.log("Volta", i);

// while — enquanto a condição for verdadeira
let energia = 3;
while (energia > 0) { console.log("Dançando..."); energia--; }

// do...while — executa pelo menos 1 vez
let n = 0;
do { console.log("Roda ao menos uma vez"); } while (n > 0);

// break e continue
for (let i = 1; i <= 5; i++) {
  if (i === 3) continue; // pula o 3
  if (i === 5) break;    // para no 5
  console.log(i);        // 1, 2, 4
}
Volta 1 Volta 2 Volta 3 Dançando... (x3) Roda ao menos uma vez 1 2 4
Loop infinito

Esquecer de atualizar a condição (i++ ou energia--) trava o navegador. Se acontecer: feche a aba. Sempre garanta que o loop tem fim.

Funções & POO

Funções

Conceito

Uma função é um bloco de código reutilizável com nome. Você define uma vez e chama quantas vezes quiser. Evita repetição e organiza o programa.

Analogia

Função é uma receita de bolo: os parâmetros são os ingredientes que entram, o corpo é o modo de preparo, e o retorno é o bolo que sai. Você escreve a receita uma vez e faz vários bolos.

funcoes.js
// Declaração — parâmetro: preço; retorno: preço com imposto
function comImposto(preco, taxa = 0.1) {
  return preco + preco * taxa;
}
console.log(comImposto(100));      // 110 (taxa padrão 10%)
console.log(comImposto(100, 0.2)); // 120

// Recursividade — função que chama a si mesma
function fatorial(n) {
  if (n <= 1) return 1;        // caso base (para a recursão)
  return n * fatorial(n - 1);  // chama a si mesma
}
console.log(fatorial(5)); // 120
110 120 120
Boas práticas

Uma função = uma responsabilidade. Nome de função é verbo (calcularTotal, validarEmail). Use parâmetros padrão para evitar undefined.

Arrow Functions

Sintaxe ES6

arrow.js
// função tradicional
function dobro(x) { return x * 2; }

// arrow equivalente
const dobroArrow = (x) => x * 2;       // return implícito
const soma = (a, b) => a + b;
const ola = () => console.log("Oi!");  // sem parâmetro
const obj = (id) => ({ id });          // retornar objeto: use ()

console.log(dobroArrow(5)); // 10
console.log(soma(2, 3));    // 5
10 5

Quando usar / evitar

Use arrowEvite arrow
Callbacks (map, filter)Métodos de objeto que usam this
Funções curtas de 1 linhaConstrutores (não dá new)
No mundo real

Arrow functions brilham com arrays: numeros.map(n => n * 2). São o padrão moderno para callbacks curtos. A diferença técnica chave é o this — arrows herdam o this do contexto onde foram criadas.

Orientação a Objetos

O que é um objeto?

Na POO (Programação Orientada a Objetos), modelamos coisas do mundo real como objetos — que têm atributos (características) e métodos (ações).

Analogia

Um carro tem atributos (cor, marca, velocidade) e métodos (acelerar, frear). A classe "Carro" é a planta do projeto; cada carro fabricado é uma instância. O molde é um; os bolos são muitos.

Criando objetos direto

// Objeto literal — pares chave: valor
const aluno = {
  nome: "Wallace",
  curso: "ADS",
  notas: [8, 9, 7],
  // método dentro do objeto
  media() {
    const soma = this.notas.reduce((a, b) => a + b, 0);
    return soma / this.notas.length;
  }
};

console.log(aluno["curso"]); // ADS (notação colchete)
console.log(aluno.media());  // 8

// adicionar / alterar propriedade
aluno.semestre = 2;
aluno.nome = "Wallace K.";

No mundo real

Objetos literais são a espinha dorsal do JS: representam um produto no estoque, a resposta de uma API (JSON), a configuração de um sistema. this aponta para o próprio objeto.

classes.js
class ContaBancaria {
  // constructor roda ao criar a instância (new)
  constructor(titular, saldo = 0) {
    this.titular = titular;  // this = a instância sendo criada
    this.saldo = saldo;
  }
  depositar(valor) {
    this.saldo += valor;
    return `Novo saldo: R$ ${this.saldo}`;
  }
  sacar(valor) {
    if (valor > this.saldo) return "Saldo insuficiente";
    this.saldo -= valor;
    return `Saque ok. Saldo: R$ ${this.saldo}`;
  }
}

const conta = new ContaBancaria("Wallace", 100); // instanciação
console.log(conta.depositar(50)); // Novo saldo: R$ 150
console.log(conta.sacar(200));    // Saldo insuficiente
Novo saldo: R$ 150 Saldo insuficiente

Getters e Setters

Permitem validar e controlar o acesso aos dados. O getter "pega" um valor (com lógica), o setter "define" (com validação).

getset.js
class Produto {
  constructor(nome, preco) {
    this.nome = nome;
    this._preco = preco; // _ = convenção de "interno"
  }
  get preco() {                    // acessa como propriedade
    return `R$ ${this._preco.toFixed(2)}`;
  }
  set preco(valor) {               // valida antes de gravar
    if (valor < 0) throw new Error("Preço não pode ser negativo");
    this._preco = valor;
  }
}
const p = new Produto("Mouse", 50);
console.log(p.preco); // get → "R$ 50.00" (sem parênteses!)
p.preco = 80;         // set → valida e grava
console.log(p.preco); // "R$ 80.00"
R$ 50.00 R$ 80.00
Boas práticas

Use setters para impedir estados inválidos (preço negativo, idade < 0). É a porta de entrada controlada dos seus dados.

Membros Privados

Campos com # (ECMAScript moderno) só podem ser acessados dentro da classe — encapsulamento de verdade.

privados.js
class Cofre {
  #senha;              // campo PRIVADO de verdade
  constructor(senha) { this.#senha = senha; }

  abrir(tentativa) {
    return tentativa === this.#senha ? "Aberto 🔓" : "Negado 🔒";
  }
}
const c = new Cofre("1234");
console.log(c.abrir("0000")); // Negado 🔒
console.log(c.abrir("1234")); // Aberto 🔓
// console.log(c.#senha);     // ❌ SyntaxError — não acessível fora
Negado 🔒 Aberto 🔓
Profissional

Diferente do _ (só convenção), o # é privacidade real garantida pela linguagem. Use para tokens, senhas, estado interno que ninguém deve mexer de fora.

DOM — Document Object Model

Conceito

O DOM é a representação da página em forma de árvore de objetos. Através do document, o JS lê, altera, cria e remove elementos HTML em tempo real.

Analogia

Se o HTML é uma casa construída, o DOM é a planta interativa dela: pelo JS você abre uma porta, pinta uma parede ou adiciona um cômodo — sem reconstruir tudo.

Manipulação de Páginas

Projeto: Lista de Tarefas (To-Do) completa

Junta tudo: DOM, eventos, arrays e template strings. Cole num arquivo .html e abra no navegador.

todo.html
<input id="tarefa" placeholder="Nova tarefa">
<button id="add">Adicionar</button>
<ul id="lista"></ul>

<script>
  const input = document.querySelector("#tarefa");
  const lista = document.querySelector("#lista");
  let tarefas = [];

  function render() {
    lista.innerHTML = tarefas
      .map((t, i) => `<li>${t} <button onclick="remover(${i})">x</button></li>`)
      .join("");
  }
  function remover(i) { tarefas.splice(i, 1); render(); }

  document.querySelector("#add").addEventListener("click", () => {
    if (input.value.trim() === "") return;
    tarefas.push(input.value);
    input.value = "";
    render();
  });
</script>
Padrão profissional

Note o padrão "estado → render": os dados ficam em tarefas (estado), e a função render() redesenha a tela a partir do estado. É a ideia central por trás do React e de toda UI moderna.

Preparação para o Mercado

Clean Code — código limpo

  • Nomes claros: calcularTotal > calc; usuarios > arr.
  • Funções pequenas: uma função, uma responsabilidade.
  • Sem números mágicos: const IMPOSTO = 0.1 em vez de espalhar 0.1.
  • Cedo retorno (early return): trate o caso inválido primeiro e saia.
  • DRY — Don't Repeat Yourself: extraia repetição em funções.

Convenções ES6+

  • const por padrão, let quando reatribui, nunca var.
  • Arrow functions em callbacks; template strings em vez de +.
  • Desestruturação: const { nome, idade } = user;
  • Spread/rest: const novo = [...antigo, item];

Banco de Questões Comentadas

Questões de revisão com gabarito explicado. Tente responder antes de abrir.

Q1 — Qual a diferença entre == e ===?

Resposta: == compara só o valor, convertendo tipos (coerção) — 5 == "5" é true. === compara valor e tipo — 5 === "5" é false. Use sempre ===.

Q2 — O que imprime console.log(typeof null)?

Resposta: "object" — bug histórico do JS mantido por compatibilidade. Para checar null use x === null.

Q3 — Por que evitar var?

Resposta: var tem escopo de função (vaza de blocos), permite redeclaração e tem hoisting que vira undefined — fonte de bugs sutis. let/const têm escopo de bloco e são mais previsíveis.

Q4 — O que faz array.map()?

Resposta: cria um novo array transformando cada elemento, sem alterar o original. Ex.: [1,2,3].map(n => n*2) → [2,4,6].

Q5 — Qual a saída de "5" + 3 e "5" - 3?

Resposta: "53" (o + com string concatena) e 2 (o - força conversão para número). Coerção implícita em ação.

Q6 — Para que serve o # numa classe?

Resposta: declara um campo privado real, acessível só dentro da classe. Diferente do _, que é apenas convenção.

Q7 — Diferença entre localStorage e sessionStorage?

Resposta: localStorage persiste indefinidamente; sessionStorage some ao fechar a aba. Ambos guardam só texto (use JSON.stringify para objetos).

Q8 — O que é hoisting?

Resposta: o mecanismo que "eleva" declarações para o topo do escopo antes da execução. Com var a variável vale undefined; com let/const fica na "zona morta temporal" (erro se usada antes).

Q9 — Quando NÃO usar arrow function?

Resposta: em métodos de objeto que dependem do this da instância, e como construtores (arrows não podem ser chamadas com new).

Q10 — O que faz reduce()?

Resposta: condensa um array em um único valor, acumulando. Ex. soma: [1,2,3].reduce((acc, n) => acc + n, 0) → 6.
