Do Zero ao Push
git · linha de comando

Guia prático para conectar a pasta trabalho-2-seguranca-cibernetica ao Git e ao GitHub, e manter o fluxo de commits do trabalho de hashes de senha em dia.

PS C:\Users\walla\Downloads\trabalho-2-seguranca-cibernetica
PS> git status On branch main # nenhum commit ainda — repositório iniciado, mas vazio Changes to be committed:   new file: trabalho_hash_senhas.py
Passo 01

Diga ao Git quem você é

01

O Git carimba cada commit com um nome e um e-mail. Isso ainda não está configurado nesta máquina — sem isso, o commit do passo seguinte falha.

identidade
PS> git config --global user.name "Seu Nome" PS> git config --global user.email "voce@exemplo.com"
por quê

Use o mesmo e-mail da sua conta no GitHub — assim os commits aparecem vinculados ao seu perfil lá.

Passo 02

Feche o primeiro commit

02

O arquivo trabalho_hash_senhas.py já está na área de staging (visto no git status acima). Falta registrar essa mudança no histórico.

primeiro commit
PS> git add . # adiciona qualquer outro arquivo novo/alterado PS> git commit -m "commit inicial: hashing de senhas"
Passo 03

Crie o repositório remoto

03

No GitHub, clique em New repository. Dê um nome (ex.: trabalho-2-seguranca-cibernetica) e não marque "Add a README" — sua pasta local já tem conteúdo, e um README remoto geraria histórico conflitante.

Copie a URL que o GitHub mostrar na tela seguinte (formato https://github.com/usuario/repo.git).

Passo 04

Conecte local ↔ remoto

04

Aponte seu repositório local para essa URL e envie o histórico pela primeira vez.

conexão remota
PS> git remote add origin https://github.com/SEU-USUARIO/SEU-REPO.git PS> git branch -M main PS> git push -u origin main
por quê

-u memoriza a dupla origin/main, então nos próximos envios basta digitar git push.

Passo 05

Autentique-se

05

O GitHub não aceita mais senha de conta no git push. Ao ser solicitado, use um Personal Access Token (Settings → Developer settings → Personal access tokens) no lugar da senha, ou configure uma chave SSH.

Passo 06

Fluxo do dia a dia

Depois da conexão inicial, é este ciclo que se repete a cada mudança no trabalho.

rotina
# 1. veja o que mudou PS> git status # 2. selecione as mudanças PS> git add trabalho_hash_senhas.py # 3. registre com uma mensagem clara PS> git commit -m "adiciona verificação de força de senha" # 4. envie para o GitHub PS> git push
Passo 07

Referência rápida

ComandoFaz o quêQuando usar
git statusMostra o que mudou e o que está pendenteAntes de qualquer outro comando
git log --onelineLista o histórico de commits, resumidoPara ver o que já foi feito
git diffMostra linha a linha o que mudouAntes de dar add
git pullTraz mudanças do GitHub para a pasta localNo início de cada sessão de trabalho
git restore <arquivo>Descarta mudanças não commitadas de um arquivoQuando você "estragou" algo local
Passo 08

Erros comuns

!
fatal: not a git repository

Você não está dentro da pasta certa. Confira com pwd (ou Get-Location) se está em trabalho-2-seguranca-cibernetica.

!
remote origin already exists

Você já rodou git remote add origin antes. Troque para git remote set-url origin <url>.

!
Support for password authentication was removed

O GitHub exige token ou SSH — veja o passo 05 acima.

!
Updates were rejected because the remote contains work...

Alguém (ou o próprio GitHub) tem commits que você não tem localmente. Rode git pull antes de tentar git push de novo.
