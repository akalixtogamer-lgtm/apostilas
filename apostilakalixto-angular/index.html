CAPÍTULO 01

O que é o Angular

COMPLEMENTO · Kalixto

O Angular é um framework front-end mantido pelo Google, escrito em TypeScript, para construir aplicações web modernas baseadas em componentes. Ele entrega, na mesma caixa, roteamento, formulários, cliente HTTP, injeção de dependência e ferramentas de build e teste.

Analogia

Pense numa coreografia. Cada componente é um bloco de movimento (um passo, uma sequência). A aplicação é a música inteira: o App chama os blocos na ordem certa. Quando um bloco muda, o resto da coreografia continua de pé.

Framework, biblioteca e ferramenta

AngularReactVue
TipoFramework completoBiblioteca de UIFramework progressivo
Linguagem padrãoTypeScriptJavaScript ou TypeScriptJavaScript ou TypeScript
Roteamento, formulários, HTTPInclusosBibliotecas externasPacotes oficiais
Estilo de projetoOpinativo, padronizadoLivreIntermediário

O que mudou até a versão 20

  • Standalone por padrão. Componentes declaram o que usam em imports. O NgModule deixou de ser necessário.
  • Novo control flow. @if, @for e @switch no template substituem *ngIf, *ngFor e *ngSwitch, que estão deprecados na v20.
  • Signals. Uma forma simples de guardar estado reativo. As APIs principais (signal, computed, effect, linkedSignal) estão estáveis na v20.
  • Nomes de arquivo mais curtos. O CLI 20 gera cadastro.ts em vez de cadastro.component.ts, e a classe se chama Cadastro.
  • Zoneless. Detecção de mudanças sem Zone.js, em prévia para desenvolvedores na v20.
Dica

Tutoriais antigos usam @NgModule, *ngIf e arquivos .component.ts. Ainda funcionam em projetos legados, mas ao estudar prefira a sintaxe moderna deste volume.

Como uma aplicação Angular é montada

index.html→main.ts→bootstrapApplication→App (raiz)→componentes filhos

Ambiente de desenvolvimento

Atenção · laboratório de faculdade

Em muitos laboratórios o PATH do npm do usuário não vem configurado. O ng falha mesmo depois de instalar o Angular CLI. A seção 2.4 mostra a correção.

2.1 Instalando o Node.js (LTS)

O Node.js é o ambiente que executa as ferramentas do Angular, principalmente o npm (gerenciador de pacotes). Instale a versão LTS em nodejs.org.

Versão exigida

O Angular 20 pede Node.js 20.19 ou superior (ou 22.12+, ou 24+). Se o seu Node for mais antigo, o ng new avisa e se recusa a continuar.

Valide no CMD (Windows → digite cmd → Enter):

Se aparecer “não é reconhecido…”, o problema quase sempre é o PATH.

2.2 Entendendo o PATH

O PATH é uma lista de pastas onde o Windows procura programas quando você digita um comando. Para ver o atual:

PastaO que é
C:\Program Files\nodejsOnde o Node costuma ficar
C:\Users\<usuário>\AppData\Roaming\npmOnde os pacotes globais (como o ng) são instalados para o usuário
Por que isso importa

Se a pasta Roaming\npm não estiver no PATH, o pacote instala, mas o comando ng continua dando “não é reconhecido…”.

2.3 Acessando a pasta AppData (oculta)

  • Opção A: Explorador de Arquivos → Exibir → marque “Itens ocultos”.
  • Opção B: na barra de endereço do Explorador, digite %appdata% e pressione Enter.

2.4 Adicionando ao PATH da conta (User PATH)

  1. Pesquise no Windows “variáveis de ambiente” e abra “Editar as variáveis de ambiente do sistema”.
  2. Clique em “Variáveis de Ambiente…”.
  3. Em “Variáveis de usuário”, selecione Path e clique em “Editar”.
  4. Clique em “Novo” e adicione C:\Users\SEU_USUARIO\AppData\Roaming\npm.
  5. Se o Node não funcionar, adicione também C:\Program Files\nodejs.
  6. Confirme com OK em todas as janelas.
  7. Feche o CMD e abra de novo. Isso é obrigatório.

Valide em um CMD novo com node -v e npm -v.

2.5 VS Code com Command Prompt

Algumas faculdades bloqueiam o PowerShell por política. Nesses casos, use o CMD dentro do VS Code:

  1. Abra o VS Code e vá em Terminal → New Terminal.
  2. No menu de perfis do painel do terminal, escolha Select Default Profile.
  3. Selecione Command Prompt.
  4. Feche o terminal atual e abra um novo.

BASE · Apostila Bootstrap e Cadastro

O Angular é baseado em componentes. Em projetos reais, separar a interface em componentes distintos melhora a organização, facilita a manutenção e prepara o sistema para crescer. No projeto-exemplo, o componente App é só o ponto de entrada. A tela do formulário vive em um componente próprio, o Cadastro.

6.1 Control flow: @if, @for e @switch

Desde a v17 o Angular tem blocos de controle de fluxo nativos no template. Eles dispensam imports e são mais legíveis que as diretivas *ngIf e *ngFor citadas em materiais antigos.

Atenção

O track do @for é obrigatório. Use um identificador único (id) para o Angular reaproveitar elementos em vez de recriar a lista inteira.

Antigo (deprecado na v20)Moderno
*ngIf="x"@if (x) { }
*ngFor="let i of lista"@for (i of lista; track i.id) { }
[ngSwitch] + *ngSwitchCase@switch + @case

6.2 Pipes

Pipes formatam valores no template sem alterar o dado original.

Para usar um pipe, importe-o no componente: imports: [UpperCasePipe, CurrencyPipe, DatePipe], todos de @angular/common.

CAPÍTULO 08

Signals e estado

COMPLEMENTO · Kalixto

Um signal é um valor que avisa o Angular quando muda. O template que o lê é atualizado sozinho, só onde precisa.

APIPara quê
signal(valor)Estado que você altera
computed(() => ...)Valor derivado, recalculado automaticamente
effect(() => ...)Efeito colateral quando um signal muda (log, localStorage)
linkedSignalEstado que reinicia quando outra fonte muda
input(), output(), model()Entradas, saídas e binding bidirecional de componentes
Regra de bolso

Para ler, chame como função: total(). Para escrever, use .set() ou .update(). Não altere o valor lendo-o e atribuindo.

Carrinho

Crie um signal itens (array de preços) e um computed chamado total que some tudo. Adicione um botão que acrescenta um item de R$ 10.

Serviços e injeção de dependência

COMPLEMENTO · Kalixto

Um serviço é uma classe que guarda lógica reutilizável (regras, acesso a dados, estado compartilhado). Componentes cuidam da tela. Serviços cuidam do resto. O Angular entrega o serviço pronto para quem pedir, e isso se chama injeção de dependência.

Para usar o serviço em um componente, peça-o com inject():

Analogia

O serviço é a secretaria da escola de dança: guarda a lista de alunos e as regras de matrícula. Cada turma (componente) pede informação à secretaria, em vez de manter a sua própria lista.

CAPÍTULO 10

APIs e HttpClient

BASE · Slides: Introdução a APIs com TypeScript (Prof. Vitor)

10.1 O que é uma API

API significa Application Programming Interface: um conjunto de regras para que softwares conversem entre si.

Analogia do garçom

Você faz o pedido (requisição) ao garçom e recebe a comida (resposta). Você não entra na cozinha. A API é o garçom entre o seu front-end e o servidor.

10.2 Como era antes das APIs

  • Troca de arquivos .txt, .xml ou .csv.
  • Integração direta entre bancos de dados.
  • Problemas: lentidão, insegurança e manutenção difícil.
  • Exemplo: um supermercado enviando a lista de produtos por um arquivo .txt, que o outro sistema precisava ler e interpretar manualmente.

10.3 Benefícios de usar APIs

COMPLEMENTO · Kalixto
  • Padronização: contrato claro de entrada e saída (geralmente JSON).
  • Tempo real: dados atualizados a cada requisição, sem esperar um arquivo.
  • Segurança: autenticação, permissões e limites por rota.
  • Reuso: o mesmo back-end atende site, app e outros sistemas.
  • Desacoplamento: front e back evoluem separados.

CAPÍTULO 11

Formulários reativos

BASE · Slides: Programação Front-End III, Reactive Forms (Prof. Vitor)

Formulários reativos são uma abordagem programática e explícita para lidar com formulários: você tem mais controle sobre estado, validações e comportamento dos campos. Em vez de definir tudo no HTML e ligar a variáveis (como nos formulários baseados em template), eles são construídos em código, no componente, com classes e objetos.

11.1 Principais características

  • Controle explícito: campos, validações e estado são criados no TypeScript, o que facilita testes e manutenção.
  • Validação síncrona e assíncrona: regras fáceis de adicionar e de ler.
  • Rastreamento de mudanças: a API mostra o estado de cada campo (sujo, válido, pronto para envio).
  • Escalabilidade: formulários complexos ficam mais fáceis de gerenciar e evoluir.

11.2 Como funciona

O ReactiveFormsModule define e gerencia o formulário, composto por três peças principais:

ClassePapel
FormControlUm campo individual
FormGroupUm conjunto de controles (input, select, etc.)
FormArrayCampos dinâmicos ou listas de controles do mesmo tipo

CAPÍTULO 12

Regex sem medo

BASE · Slides Reactive Forms (Prof. Vitor)

Regex, ou expressão regular, é uma sequência de caracteres que forma um padrão de pesquisa. Serve para encontrar, validar, substituir ou dividir textos, e existe em JavaScript, Python, Java, C# e outras linguagens.

12.1 O que o Regex faz

  • Encontrar padrões: achar uma sequência que corresponde ao padrão.
  • Substituir: trocar partes de uma string com base no padrão.
  • Validar: verificar se um e-mail, uma senha ou um CPF segue o formato.
  • Dividir: quebrar uma string por um delimitador.

12.2 Caracteres que você precisa conhecer

COMPLEMENTO · Kalixto
SímboloSignificadoExemplo
^ e $Início e fim do texto^abc$ só casa com “abc”
.Qualquer caracterea.c casa com “abc”, “a1c”
[abc] · [A-Z]Um caractere do conjunto ou faixa[0-9] um dígito
\d · \w · \sDígito · letra, número ou _ · espaço\d\d dois dígitos
* · + · ?0 ou mais · 1 ou mais · 0 ou 1ab+ “ab”, “abb”
{n,m}Entre n e m repetições\d{8,16}
( )Grupo(ab)+
(?=...)Lookahead: “daqui para frente existe...” sem consumir(?=.*\d)

12.3 Desmontando a regex da senha

Cada (?=...) é uma regra independente. Para adicionar uma regra nova, adicione outro lookahead.

12.4 Receitas prontas

UsoRegex
E-mail simples/^[^\s@]+@[^\s@]+\.[^\s@]+$/
CEP/^\d{5}-?\d{3}$/
Telefone BR/^\(?\d{2}\)?\s?9?\d{4}-?\d{4}$/
CPF com máscara/^\d{3}\.\d{3}\.\d{3}-\d{2}$/
Cuidado

Regex confere o formato, não a existência. Um CPF com formato certo pode ser inválido (dígitos verificadores). Valide dados críticos também no servidor.

Teste suas expressões em regex101.com antes de colocá-las no código.

Mini-laboratório

No console do navegador, rode /\d{5}-?\d{3}/.test('20010-000'). Troque a entrada por valores que devem falhar e confirme que retornam false.

RxJS essencial

COMPLEMENTO · Kalixto

RxJS é a biblioteca de programação reativa usada pelo Angular. Um Observable representa um fluxo de valores ao longo do tempo (uma resposta HTTP, cliques, digitação). Você só recebe os valores se se inscrever nele.

OperadorUso
mapTransforma cada valor
filterDeixa passar só o que atende a condição
switchMapTroca para um novo Observable e cancela o anterior (busca por digitação)
debounceTimeEspera o usuário parar de digitar
catchErrorTrata falhas e devolve um valor alternativo
takeUntilDestroyedCancela a inscrição quando o componente é destruído

15.2 Build de produção

15.3 Publicando no GitHub Pages

O GitHub Pages serve sites estáticos, o que combina com uma SPA Angular. O app fica em https://usuario.github.io/nome-do-repo/, então o base href precisa conter o nome do repositório.

Rotas em páginas estáticas

O GitHub Pages não sabe redirecionar /usuarios para o index.html. Se você der F5 em uma rota interna, verá 404. Copie o index.html para 404.html após o build, ou use rotas com hash (withHashLocation()).

CAPÍTULO 16

Boas práticas

COMPLEMENTO · Kalixto
  • Um componente, uma responsabilidade. Quando o template passar de uns 150 linhas, divida.
  • Lógica fora do componente. Regras e acesso a dados vão para serviços.
  • Tipos em tudo. Evite any. Crie interfaces para as respostas da API.
  • Signals para estado local e Observables para fluxos assíncronos.
  • Organize por funcionalidade: usuarios/, pedidos/, cada uma com seus componentes, serviços e rotas.
  • Lazy loading para áreas grandes ou pouco usadas.
  • Acessibilidade: todo input com label, botões com texto claro, contraste suficiente.
  • Formate e analise o código: Prettier e ESLint (ng add angular-eslint).
  • Segredos nunca no front-end. Tudo que está no bundle é público.

Estrutura sugerida para projetos maiores

src/app/
├── core/            serviços únicos (auth, interceptors, guards)
├── shared/          componentes, pipes e diretivas reutilizáveis
├── features/
│   ├── usuarios/    lista, cadastro, usuario-api.ts, usuarios.routes.ts
│   └── pedidos/
├── app.config.ts
└── app.routes.ts
