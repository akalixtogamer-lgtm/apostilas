02Por quê

Por que Collections e Generics existem?

O problema real

Quase todo software lida com grupos de coisas: os alunos de uma turma, os itens de um carrinho, os e-mails já cadastrados, os pedidos esperando na cozinha, o estoque de cada produto. O array resolve parte disso, mas tem um defeito de nascença: o tamanho é fixo. Se você criou espaço para 30 alunos e chegou o 31º, precisa criar outro array maior e copiar tudo à mão.

Além do tamanho, cada problema pede uma operação diferente: às vezes você quer manter a ordem, às vezes proibir repetidos, às vezes achar algo pela chave, às vezes atender por ordem de chegada. Escrever essas estruturas do zero em cada projeto seria caro e cheio de bugs.

Um pouco de história

AnoVersãoO que mudou
1996JDK 1.0Só Vector, Hashtable e Stack, sem interfaces comuns entre eles.
1998JDK 1.2Nasce o Java Collections Framework, projetado por Joshua Bloch: interfaces (Collection, List, Set, Map) + implementações + algoritmos (Collections.sort).
2004J2SE 5.0Chegam os Generics (List<String>), o enhanced-for e o autoboxing. Fim dos casts manuais.
2011Java 7Operador diamante <>: new ArrayList<>().
2014Java 8Lambdas, forEach, removeIf, Comparator.comparing, Map.merge e Streams.
2017Java 9Fábricas imutáveis List.of, Set.of, Map.of (JEP 269).
2023Java 21Sequenced Collections (JEP 431): getFirst(), getLast(), reversed().
Ideia central

Collections dão as estruturas prontas; Generics garantem, já na compilação, que só entra nelas o tipo certo.

Analogias do dia a dia

Programe para a interface

Repare no lado esquerdo da declaração: List<String> nomes = new ArrayList<>();. A variável é do tipo da interface (List), e só o new escolhe a implementação (ArrayList). Assim, se amanhã você precisar trocar por LinkedList, muda uma palavra e o resto do código continua igual.

Main.java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        // Array: tamanho fixo
        String[] fixo = new String[2];
        fixo[0] = "Ana";
        fixo[1] = "Bruno";
        System.out.println("Array: " + Arrays.toString(fixo));

        // Coleção: cresce conforme a necessidade
        List<String> nomes = new ArrayList<>();
        nomes.add("Ana");
        nomes.add("Bruno");
        nomes.add("Carla");   // sem precisar redimensionar nada
        System.out.println("List: " + nomes + " (tamanho " + nomes.size() + ")");
    }
}
Saída no console
Array: [Ana, Bruno]
List: [Ana, Bruno, Carla] (tamanho 3)

Map não é uma Collection. Ele não tem add(), tem put(); e não se percorre um Map diretamente, e sim uma das suas “visões”: keySet(), values() ou entrySet().

Main.java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<String> alunos = new ArrayList<>();
        alunos.add("Ana");
        alunos.add("Bruno");
        alunos.add("Ana");          // List aceita repetidos
        alunos.set(1, "Carla");     // troca "Bruno" por "Carla"
        System.out.println(alunos.get(0));
        System.out.println(alunos.contains("Carla"));
        System.out.println(alunos.size());
        alunos.remove("Ana");       // remove só a PRIMEIRA "Ana"
        System.out.println(alunos);
    }
}
Saída no console
Ana
true
3
[Carla, Ana]

Lendo o exemplo linha a linha

  1. List<String> alunos = new ArrayList<>(); — cria uma lista vazia que só aceita String. O <> vazio (diamante) deixa o compilador deduzir o tipo pelo lado esquerdo.
  2. Depois dos três add, a lista é [Ana, Bruno, Ana]: a ordem é a de inserção e o repetido entrou.
  3. set(1, "Carla") troca a posição 1: [Ana, Carla, Ana].
  4. remove("Ana") procura com equals() e remove só a primeira ocorrência: [Carla, Ana].
!

Cuidado com List<Integer>

Em List<Integer> n, n.remove(1) remove a posição 1, não o número 1. Para remover o valor, use n.remove(Integer.valueOf(1)).

ArrayList × LinkedList

ArrayList guarda os elementos num array contíguo: ler get(i) é instantâneo, mas inserir no meio obriga a deslocar os vizinhos. LinkedList é uma lista duplamente encadeada: inserir nas pontas é barato, mas achar a posição i exige caminhar nó a nó. Na prática, ArrayList é a escolha padrão; para fila ou pilha, prefira ArrayDeque.

06Iteração

Percorrendo uma List

Quatro jeitos, cada um com seu momento.

Main.java
import java.util.Iterator;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<String> nomes = List.of("Ana", "Bruno", "Carla");

        // 1) enhanced-for: o mais legível quando você só precisa do elemento
        for (String nome : nomes) {
            System.out.println(nome);
        }

        // 2) forEach + method reference (Java 8+)
        nomes.forEach(System.out::println);

        // 3) índice: quando a POSIÇÃO importa
        for (int i = 0; i < nomes.size(); i++) {
            System.out.println(i + ": " + nomes.get(i));
        }

        // 4) Iterator: controle total (é o que o enhanced-for usa por baixo)
        Iterator<String> it = nomes.iterator();
        while (it.hasNext()) {
            System.out.println("-> " + it.next());
        }
    }
}

Removendo enquanto percorre

Chamar lista.remove(x) dentro de um enhanced-for quebra o Iterator escondido e lança ConcurrentModificationException. Há duas saídas seguras: iterator.remove() ou, mais simples, removeIf.

Main.java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> numeros = new ArrayList<>(List.of(1, 2, 3, 4, 5, 6));

        try {
            for (Integer n : numeros) {
                if (n % 2 == 0) numeros.remove(n);   // ERRADO
            }
        } catch (java.util.ConcurrentModificationException e) {
            System.out.println("Erro: " + e.getClass().getSimpleName());
        }

        List<Integer> outros = new ArrayList<>(List.of(1, 2, 3, 4, 5, 6));
        outros.removeIf(n -> n % 2 == 0);           // CERTO
        System.out.println(outros);
    }
}
Saída no console
Erro: ConcurrentModificationException
[1, 3, 5]
i

Por que new ArrayList<>(List.of(...))?

List.of() cria uma lista imutável: add, remove e removeIf lançam UnsupportedOperationException. Para editar, copie para uma ArrayList.

07Set

Set: elementos únicos

Um Set não admite duplicatas. “Duplicata” é decidida por equals() e hashCode().

Main.java
import java.util.HashSet;
import java.util.Set;

public class Main {
    public static void main(String[] args) {
        Set<String> emails = new HashSet<>();
        System.out.println(emails.add("ana@email.com"));    // true: entrou
        emails.add("bruno@email.com");
        System.out.println(emails.add("ana@email.com"));    // false: já existia

        System.out.println(emails.size());
        for (String email : emails) {
            System.out.println(email);
        }
    }
}
Saída no console
true
false
2
ana@email.com
bruno@email.com

Repare que add() devolve false quando o elemento já existe. Isso é útil para validar cadastros: “se não entrou, é porque o e-mail já estava registrado”.

Como o HashSet acha as coisas tão rápido

LinkedHashSet × TreeSet

Main.java
import java.util.HashSet;
import java.util.LinkedHashSet;
import java.util.Set;
import java.util.TreeSet;

public class Main {
    public static void main(String[] args) {
        Set<String> insercao = new LinkedHashSet<>();
        insercao.add("Zoe");
        insercao.add("Ana");
        insercao.add("Bruno");

        Set<String> hash = new HashSet<>(insercao);
        Set<String> ordenado = new TreeSet<>(insercao);

        System.out.println("LinkedHashSet: " + insercao);   // ordem de inserção
        System.out.println("TreeSet:       " + ordenado);   // ordem natural (alfabética)
        System.out.println("HashSet:       " + hash);       // ordem NÃO garantida
    }
}
Saída no console

Set com objetos seus: equals() e hashCode()

Com String e Integer funciona “sozinho” porque essas classes já implementam equals/hashCode. Com uma classe sua, se você não implementar, dois objetos com os mesmos dados serão considerados diferentes. A forma moderna de resolver é usar record (Java 16+), que gera equals, hashCode e toString automaticamente.

Main.java
import java.util.HashSet;
import java.util.Objects;
import java.util.Set;

public class Main {
    // Classe comum SEM equals/hashCode
    static class AlunoSemEquals {
        String cpf;
        AlunoSemEquals(String cpf) { this.cpf = cpf; }
    }

    // Classe comum COM equals/hashCode coerentes
    static class Aluno {
        private final String cpf;
        Aluno(String cpf) { this.cpf = cpf; }

        @Override public boolean equals(Object o) {
            if (this == o) return true;
            if (!(o instanceof Aluno outro)) return false;
            return cpf.equals(outro.cpf);
        }
        @Override public int hashCode() { return Objects.hash(cpf); }
    }

    // record: equals/hashCode/toString gerados pelo compilador
    record AlunoRecord(String cpf, String nome) {}

    public static void main(String[] args) {
        Set<AlunoSemEquals> a = new HashSet<>();
        a.add(new AlunoSemEquals("123"));
        a.add(new AlunoSemEquals("123"));
        System.out.println("Sem equals: " + a.size());   // 2 (duplicou!)

        Set<Aluno> b = new HashSet<>();
        b.add(new Aluno("123"));
        b.add(new Aluno("123"));
        System.out.println("Com equals: " + b.size());   // 1

        Set<AlunoRecord> c = new HashSet<>();
        c.add(new AlunoRecord("123", "Ana"));
        c.add(new AlunoRecord("123", "Ana"));
        System.out.println("Record: " + c);
    }
}
Saída no console
Sem equals: 2
Com equals: 1
Record: [AlunoRecord[cpf=123, nome=Ana]]
08Map

Map: chave → valor

Um Map associa cada chave única a um valor. Colocar de novo a mesma chave substitui o valor antigo.

Main.java
import java.util.HashMap;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        Map<String, Integer> estoque = new HashMap<>();
        estoque.put("Mouse", 10);
        estoque.put("Teclado", 5);
        estoque.put("Mouse", 12);        // mesma chave: substitui 10 por 12

        System.out.println(estoque.get("Mouse"));
        System.out.println(estoque.get("Monitor"));               // null
        System.out.println(estoque.getOrDefault("Monitor", 0));   // 0
        System.out.println(estoque.containsKey("Teclado"));

        for (Map.Entry<String, Integer> item : estoque.entrySet()) {
            System.out.println(item.getKey() + " = " + item.getValue());
        }
    }
}
Saída no console
12
null
0
true
Mouse = 12
Teclado = 5

Métodos modernos que economizam linhas

Contar ocorrências é um dos usos mais comuns de Map. Compare a versão “à moda antiga” com merge e computeIfAbsent:

Main.java
import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.TreeMap;

public class Main {
    public static void main(String[] args) {
        String[] palavras = "samba forró samba jazz samba forró".split(" ");

        // Contagem com merge: se não existe, põe 1; se existe, soma 1
        Map<String, Integer> contagem = new TreeMap<>();
        for (String p : palavras) {
            contagem.merge(p, 1, Integer::sum);
        }
        System.out.println(contagem);

        // Agrupamento com computeIfAbsent: cria a lista só na primeira vez
        Map<Character, List<String>> porInicial = new TreeMap<>();
        for (String p : List.of("Ana", "Bruno", "Alice", "Carla", "Beatriz")) {
            porInicial.computeIfAbsent(p.charAt(0), k -> new ArrayList<>()).add(p);
        }
        System.out.println(porInicial);
    }
}
Saída no console
{forró=2, jazz=1, samba=3}
{A=[Ana, Alice], B=[Bruno, Beatriz], C=[Carla]}

HashMap × LinkedHashMap × TreeMap

A lógica é a mesma dos Sets (na verdade, HashSet usa um HashMap por dentro): HashMap não garante ordem e é o mais rápido; LinkedHashMap mantém a ordem de inserção; TreeMap mantém as chaves ordenadas e oferece firstKey(), headMap(), ceilingKey() e afins.

Queue, Deque e PriorityQueue

Quando a pergunta é “quem é o próximo?”.

Main.java
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.PriorityQueue;
import java.util.Queue;

public class Main {
    public static void main(String[] args) {
        // Fila FIFO
        Queue<String> fila = new ArrayDeque<>();
        fila.offer("Cliente A");
        fila.offer("Cliente B");
        fila.offer("Cliente C");
        System.out.println("Próximo: " + fila.peek());
        while (!fila.isEmpty()) {
            System.out.println("Atendendo " + fila.poll());
        }

        // Pilha LIFO com Deque
        Deque<String> desfazer = new ArrayDeque<>();
        desfazer.push("digitou 'Olá'");
        desfazer.push("apagou palavra");
        desfazer.push("colou imagem");
        System.out.println("Ctrl+Z desfaz: " + desfazer.pop());

        // Fila de prioridade: sai sempre o MENOR (ordem natural)
        Queue<Integer> urgencia = new PriorityQueue<>();
        urgencia.offer(5);
        urgencia.offer(1);
        urgencia.offer(3);
        System.out.print("Prioridade: ");
        while (!urgencia.isEmpty()) System.out.print(urgencia.poll() + " ");
        System.out.println();
    }
}
Saída no console
Próximo: Cliente A
Atendendo Cliente A
Atendendo Cliente B
Atendendo Cliente C
Ctrl+Z desfaz: colou imagem
Prioridade: 1 3 5
10Ordem

Ordenação com Comparable e Comparator

Ordem natural é a que o objeto “sabe” sozinho; o Comparator é uma regra que você entrega de fora.

Comparable<T>

Ordem natural

A própria classe implementa compareTo. String ordena alfabeticamente, Integer numericamente. Só existe uma ordem natural.

Comparator<T>

Ordem sob medida

Um objeto separado com a regra. Você pode ter quantos quiser: por nome, por nota, por idade, invertido…

Main.java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

public class Main {
    record Aluno(String nome, double nota, int idade) {}

    public static void main(String[] args) {
        List<String> nomes = new ArrayList<>(List.of("Zoe", "Ana", "Bruno"));
        nomes.sort(Comparator.naturalOrder());
        System.out.println(nomes);
        nomes.sort(Comparator.reverseOrder());
        System.out.println(nomes);

        List<Aluno> turma = new ArrayList<>(List.of(
            new Aluno("Carla", 8.5, 22),
            new Aluno("Ana", 9.0, 19),
            new Aluno("Bruno", 8.5, 20)
        ));

        // Maior nota primeiro; empate decidido pelo nome
        turma.sort(Comparator.comparingDouble(Aluno::nota).reversed()
                             .thenComparing(Aluno::nome));
        turma.forEach(a -> System.out.println(a.nome() + " - " + a.nota()));
    }
}
Saída no console
[Ana, Bruno, Zoe]
[Zoe, Bruno, Ana]
Ana - 9.0
Bruno - 8.5
Carla - 8.5
i

Collections.sort(lista) ou lista.sort(...)?

Fazem o mesmo. Collections.sort(lista) usa a ordem natural; lista.sort(comparator) (Java 8+) é a forma mais direta quando você tem um Comparator. Passar null para lista.sort também usa a ordem natural.

11Java moderno

Coleções imutáveis e Sequenced Collections

Coleção imutável é aquela que não pode ser alterada depois de criada. Ela evita uma classe inteira de bugs (“quem mexeu nessa lista?”) e é segura para compartilhar entre threads.

FormaO que geraObservação
List.of(a, b), Set.of, Map.ofColeção imutável novaNão aceita null; Set.of e Map.of recusam repetidos
List.copyOf(outra)Cópia imutávelMudanças na original não afetam a cópia
Collections.unmodifiableList(l)“Vista” somente-leituraSe a original mudar, a vista mostra a mudança

Sequenced Collections (Java 21)

Antes do Java 21, pegar o último elemento era diferente em cada tipo: list.get(list.size() - 1), deque.getLast(), sortedSet.last()… A JEP 431 criou as interfaces SequencedCollection, SequencedSet e SequencedMap, com métodos uniformes para coleções que têm ordem definida.

Main.java
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.SequencedMap;

public class Main {
    public static void main(String[] args) {
        List<String> ranking = new ArrayList<>(List.of("Ana", "Bruno", "Carla"));
        System.out.println(ranking.getFirst() + " / " + ranking.getLast());
        System.out.println(ranking.reversed());

        SequencedMap<String, Integer> pedidos = new LinkedHashMap<>();
        pedidos.put("#101", 2);
        pedidos.put("#102", 1);
        pedidos.put("#103", 4);
        System.out.println("Primeiro pedido: " + pedidos.firstEntry());

        List<String> fixa = List.of("x", "y");
        try {
            fixa.add("z");
        } catch (UnsupportedOperationException e) {
            System.out.println("List.of é imutável");
        }
    }
}
Saída no console
Ana / Carla
[Carla, Bruno, Ana]
Primeiro pedido: #101=2
List.of é imutável

12Motivação

Generics: por que usar?

Mover o erro do momento em que o usuário está usando o sistema para o momento em que você está compilando.

Antes do Java 5, uma List guardava Object. Você podia colocar qualquer coisa, e na hora de ler precisava fazer cast. Se alguém tivesse colocado o tipo errado, o erro só aparecia em execução, com ClassCastException.

Antes.java
// Sem generics (raw type) — compila, mas explode em execução
List notas = new ArrayList();
notas.add(8);

14<T> no método

Métodos genéricos e tipos limitados

Um método pode declarar seu próprio <T>, mesmo dentro de uma classe que não é genérica.

Main.java
import java.util.List;

public class Main {
    // <T> antes do retorno declara o parâmetro de tipo do método
    public static <T> void exibir(T valor) {
        System.out.println("Valor: " + valor);
    }

    // Retorna o mesmo tipo que recebeu
    public static <T> T primeiro(List<T> lista) {
        return lista.get(0);
    }

    // Tipo LIMITADO: T precisa saber se comparar (ter compareTo)
    public static <T extends Comparable<T>> T maior(List<T> lista) {
        T m = lista.get(0);
        for (T item : lista) {
            if (item.compareTo(m) > 0) m = item;
        }
        return m;
    }

    public static void main(String[] args) {
        exibir("Java");
        exibir(123);
        exibir(true);

        String s = primeiro(List.of("Ana", "Bruno"));   // sem cast
        System.out.println(s);

        System.out.println(maior(List.of(3, 9, 4)));
        System.out.println(maior(List.of("pera", "uva", "abacaxi")));
    }
}

15? extends · ? super

Wildcards e a regra PECS

List<Integer> não é filha de List<Number>, mesmo Integer sendo filho de Number. Os wildcards resolvem isso.

Por que não é filha? Se fosse, você poderia passar uma List<Integer> para um método que recebe List<Number> e ele faria lista.add(3.14): um Double dentro de uma lista de inteiros. Para impedir isso, generics são invariantes. O coringa ? afrouxa a regra de forma controlada.

? extends Number — ler números de qualquer lista numérica

Main.java
import java.util.List;

public class Main {
    static double somar(List<? extends Number> numeros) {
        double total = 0;
        for (Number n : numeros) {
            total += n.doubleValue();
        }
        // numeros.add(1);  // não compila: a lista pode ser de Double!
        return total;
    }

    public static void main(String[] args) {
        System.out.println(somar(List.of(1, 2, 3)));      // List<Integer>
        System.out.println(somar(List.of(1.5, 2.5)));     // List<Double>
    }
}

19Mão na massa

Projeto: sistema de turmas de um studio de dança

Um programa só, usando quase tudo desta apostila: record, Set, Queue, Map, Comparator, merge e uma classe genérica.

Requisitos

  1. Cada turma tem um estilo (samba, forró, jazz funk…) e um número máximo de vagas.
  2. Um aluno não pode ser matriculado duas vezes na mesma turma (Set).
  3. Turma cheia manda o aluno para a lista de espera, por ordem de chegada (Queue).
  4. Quando alguém sai, o primeiro da espera entra automaticamente.
  5. As turmas são encontradas pelo nome do estilo, em ordem alfabética (TreeMap).
  6. Relatório: alunos ordenados por idade e depois por nome (Comparator), e contagem por faixa etária (merge).
  7. Um Repositorio<K, T> genérico guarda qualquer entidade por chave.
Main.java
import java.util.*;

public class Main {

    // ---------- Entidade ----------
    record Aluno(String cpf, String nome, int idade) {
        @Override public String toString() { return nome + " (" + idade + ")"; }
    }

    // ---------- Repositório genérico ----------
    static class Repositorio<K, T> {
        private final Map<K, T> dados = new LinkedHashMap<>();
        void salvar(K chave, T valor) { dados.put(chave, valor); }
        Optional<T> buscar(K chave) { return Optional.ofNullable(dados.get(chave)); }
        Collection<T> todos() { return dados.values(); }
    }

    // ---------- Turma ----------
    static class Turma {
        private final String estilo;
        private final int vagas;
        private final Set<Aluno> matriculados = new LinkedHashSet<>();
        private final Queue<Aluno> espera = new ArrayDeque<>();

        Turma(String estilo, int vagas) { this.estilo = estilo; this.vagas = vagas; }

        String matricular(Aluno a) {
            if (matriculados.contains(a) || espera.contains(a)) return a.nome() + " já está nesta turma";
            if (matriculados.size() < vagas) {
                matriculados.add(a);
                return a.nome() + " matriculado(a) em " + estilo;
            }
            espera.offer(a);
            return a.nome() + " foi para a espera de " + estilo + " (posição " + espera.size() + ")";
        }

        String cancelar(Aluno a) {
            if (!matriculados.remove(a)) return a.nome() + " não estava matriculado(a)";
            Aluno proximo = espera.poll();
            if (proximo == null) return a.nome() + " saiu de " + estilo;
            matriculados.add(proximo);
            return a.nome() + " saiu; " + proximo.nome() + " entrou da espera";
        }

        Set<Aluno> alunos() { return Collections.unmodifiableSet(matriculados); }
        int naEspera() { return espera.size(); }
    }

    static String faixa(int idade) {
        if (idade < 18) return "0-17";
        if (idade < 30) return "18-29";
        return "30+";
    }

    public static void main(String[] args) {
        Repositorio<String, Aluno> alunos = new Repositorio<>();
        alunos.salvar("111", new Aluno("111", "Ana", 24));
        alunos.salvar("222", new Aluno("222", "Bruno", 31));
        alunos.salvar("333", new Aluno("333", "Carla", 17));
        alunos.salvar("444", new Aluno("444", "Diego", 24));
        alunos.salvar("555", new Aluno("555", "Eva", 45));

        Map<String, Turma> turmas = new TreeMap<>();
        turmas.put("samba", new Turma("samba", 2));
        turmas.put("forró", new Turma("forró", 3));
        turmas.put("jazz funk", new Turma("jazz funk", 2));

        Turma samba = turmas.get("samba");
        for (String cpf : List.of("111", "222", "333", "111")) {
            alunos.buscar(cpf).ifPresent(a -> System.out.println(samba.matricular(a)));
        }
        alunos.buscar("111").ifPresent(a -> System.out.println(samba.cancelar(a)));

        Turma forro = turmas.get("forró");
        for (Aluno a : alunos.todos()) forro.matricular(a);

        System.out.println("\n== Turmas (ordem alfabética) ==");
        turmas.forEach((estilo, t) ->
            System.out.println(estilo + ": " + t.alunos() + " | espera: " + t.naEspera()));

        System.out.println("\n== Forró por idade e nome ==");
        List<Aluno> relatorio = new ArrayList<>(forro.alunos());
        relatorio.sort(Comparator.comparingInt(Aluno::idade).thenComparing(Aluno::nome));
        relatorio.forEach(System.out::println);

        System.out.println("\n== Alunos cadastrados por faixa etária ==");
        Map<String, Integer> porFaixa = new TreeMap<>();
        for (Aluno a : alunos.todos()) porFaixa.merge(faixa(a.idade()), 1, Integer::sum);
        System.out.println(porFaixa);
    }
}

21Profissional

Boas práticas

  1. Declare pela interface: List<T>, Set<T>, Map<K,V> na variável, no parâmetro e no retorno.
  2. Devolva coleção vazia, nunca null: return List.of(); evita if (lista != null) espalhado pelo código.
  3. Prefira imutáveis quando não houver motivo para alterar: List.of, List.copyOf.
  4. Não exponha a coleção interna: devolva Collections.unmodifiableList(...) ou uma cópia (como a Turma do projeto).
  5. Use record para dados que entram em Set e como chave de Map.
  6. Nomeie no plural: alunos, emailsCadastrados, estoquePorProduto.
  7. Defina capacidade inicial quando souber o tamanho: new ArrayList<>(10_000).
  8. Aplique PECS em métodos públicos que recebem coleções: deixa sua API mais flexível.
  9. Conheça Collections e Arrays: sort, shuffle, frequency, max, min, nCopies já estão prontos.

6Quando usar HashSet, LinkedHashSet ou TreeSet?intermediário
Resposta

HashSet quando só importa a unicidade e a velocidade; LinkedHashSet quando também importa a ordem de inserção (ex.: histórico sem repetição); TreeSet quando os elementos precisam estar sempre ordenados (ex.: ranking, palavras em ordem alfabética), pagando O(log n).

9Use uma pilha (Deque) para verificar se os parênteses de "(a[b]{c})" estão balanceados.intermediário
Solução
Main.java
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.Map;

public class Main {
    static boolean balanceado(String s) {
        Map<Character, Character> par = Map.of(')', '(', ']', '[', '}', '{');
        Deque<Character> pilha = new ArrayDeque<>();
        for (char c : s.toCharArray()) {
            if (c == '(' || c == '[' || c == '{') pilha.push(c);
            else if (par.containsKey(c)) {
                if (pilha.isEmpty() || pilha.pop() != par.get(c)) return false;
            }
        }
        return pilha.isEmpty();
    }

    public static void main(String[] args) {
        System.out.println(balanceado("(a[b]{c})"));
        System.out.println(balanceado("(a[b)c]"));
    }
}
Saída no console
true
false
10Por que este código não compila? List<Number> n = new ArrayList<Integer>();intermediário
Resposta

Generics são invariantes: List<Integer> não é subtipo de List<Number>. Se fosse, seria possível fazer n.add(3.14) numa lista de inteiros. Para aceitar “lista de algum tipo numérico” na leitura, use List<? extends Number>.

12Crie uma classe genérica Ranking<T> que guarda no máximo N itens e sempre devolve os N melhores segundo um Comparator.avançado
Solução
Main.java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;
import java.util.PriorityQueue;

public class Main {
    static class Ranking<T> {
        private final int limite;
        private final Comparator<T> criterio;
        private final PriorityQueue<T> fila;   // o PIOR fica no topo para sair primeiro

        Ranking(int limite, Comparator<T> criterio) {
            this.limite = limite;
            this.criterio = criterio;
            this.fila = new PriorityQueue<>(criterio);
        }

        void registrar(T item) {
            fila.offer(item);
            if (fila.size() > limite) fila.poll();
        }

        List<T> melhores() {
            List<T> lista = new ArrayList<>(fila);
            lista.sort(criterio.reversed());
            return lista;
        }
    }

    record Pontuacao(String jogador, int pontos) {}

    public static void main(String[] args) {
        Ranking<Pontuacao> top3 = new Ranking<>(3, Comparator.comparingInt(Pontuacao::pontos));
        top3.registrar(new Pontuacao("Ana", 120));
        top3.registrar(new Pontuacao("Bruno", 300));
        top3.registrar(new Pontuacao("Carla", 90));
        top3.registrar(new Pontuacao("Diego", 250));
        top3.registrar(new Pontuacao("Eva", 180));
        top3.melhores().forEach(p -> System.out.println(p.jogador() + ": " + p.pontos()));
    }
}

Desafio

★Simule o atendimento de uma academia: alunos chegam numa fila; os do plano “premium” têm prioridade, e entre iguais vale a ordem de chegada.desafio
Dica e solução

A PriorityQueue sozinha não garante a ordem de chegada entre empates; inclua um número de chegada no critério de desempate.

Main.java
import java.util.Comparator;
import java.util.PriorityQueue;

public class Main {
    record Chegada(String nome, boolean premium, int ordem) {}

    public static void main(String[] args) {
        PriorityQueue<Chegada> fila = new PriorityQueue<>(
            Comparator.comparing((Chegada c) -> !c.premium())   // false (premium) vem antes
                      .thenComparingInt(Chegada::ordem));
        String[][] dados = {{"Ana", "n"}, {"Bruno", "s"}, {"Carla", "n"}, {"Diego", "s"}};
        int ordem = 0;
        for (String[] d : dados) fila.offer(new Chegada(d[0], d[1].equals("s"), ordem++));
        while (!fila.isEmpty()) {
            Chegada c = fila.poll();
            System.out.println(c.nome() + (c.premium() ? " (premium)" : ""));
        }
    }
}
Saída no console

Diego (premium)

Perguntas de entrevista

Aparecem com frequência em processos para estágio e júnior Java.

?Qual a diferença entre ArrayList e LinkedList?clássica

Array dinâmico × lista duplamente encadeada. ArrayList tem acesso por índice O(1) e melhor uso de cache; LinkedList insere/remove nas pontas em O(1), mas acessar a posição i custa O(n). Na prática, ArrayList vence quase sempre.

?Como o HashMap funciona por dentro?clássica

Um array de “baldes”. O hashCode() da chave escolhe o balde; colisões ficam no mesmo balde e são resolvidas com equals(). Quando o mapa passa de um fator de carga (0,75 por padrão), o array dobra e tudo é redistribuído. Desde o Java 8, baldes com muitas colisões viram árvores.

?Qual o contrato entre equals() e hashCode()?clássica

Se a.equals(b) é true, então a.hashCode() == b.hashCode(). O contrário não é obrigatório (colisões são permitidas). Quebrar a regra faz HashSet/HashMap “perderem” objetos.

?O que é type erasure?intermediária

O compilador verifica os tipos genéricos e os remove do bytecode, inserindo casts. Por isso não existe new T() nem instanceof List<String>, e List<String> e List<Integer> são a mesma classe em execução.

?Explique PECS.intermediária

Producer Extends, Consumer Super (Joshua Bloch, Effective Java). Se o parâmetro produz valores que você lê, use ? extends T; se consome valores que você escreve, use ? super T.

?Diferença entre Comparable e Comparator?clássica

Comparable define a ordem natural dentro da própria classe (compareTo), e só existe uma. Comparator é uma regra externa (compare), e você pode ter várias.

?Collections.unmodifiableList e List.copyOf são a mesma coisa?intermediária

Não. unmodifiableList é uma vista somente-leitura: mudanças na lista original aparecem nela. List.copyOf cria uma cópia imutável independente.

Glossário

Autoboxing
Conversão automática de primitivo para wrapper (int → Integer); o inverso é unboxing.
Bucket (balde)
Posição do array interno de uma tabela hash.
Diamante
O <> vazio em new ArrayList<>(), que deixa o compilador inferir o tipo.
FIFO / LIFO
First In First Out (fila) / Last In First Out (pilha).
Imutável
Objeto ou coleção que não pode ser alterado depois de criado.
Invariância
List<Integer> não é subtipo de List<Number>.
Iterator
Objeto que percorre uma coleção com hasNext()/next() e permite remove() seguro.
Parâmetro de tipo
A variável de tipo (T, E, K, V) declarada entre <>.
PECS
Producer Extends, Consumer Super: regra para escolher o wildcard.
Raw type
Tipo genérico usado sem argumento (List); existe só por compatibilidade.
Type erasure
Remoção dos tipos genéricos no bytecode após a verificação do compilador.
Wildcard
O coringa ?, sozinho ou com extends/super.
Wrapper
Classe que embrulha um primitivo: Integer, Double, Boolean…
