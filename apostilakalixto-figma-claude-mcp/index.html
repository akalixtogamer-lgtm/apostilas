Módulo 01 · Fundamentos

A Revolução da IA no Design e Desenvolvimento

Para entender para onde vamos, precisamos olhar de onde viemos. Este módulo conta a história curta — porém intensa — de como construir para a web deixou de ser tarefa de poucos especialistas e se tornou um campo onde método, design e inteligência artificial caminham juntos.

1.1 A evolução do desenvolvimento web

No começo, a web era feita de páginas estáticas: arquivos HTML soltos, com pouca formatação e nenhuma interação. Construir um site era escrever marcação à mão e subir para um servidor. O foco era o documento, não a experiência.

Veio o CSS e separou o conteúdo da aparência. Depois o JavaScript trouxe interatividade. Surgiram os sistemas dinâmicos (PHP, depois bancos de dados acoplados às páginas), e a web virou software. Na década seguinte, os frameworks de front-end — React, Vue, Angular — transformaram a interface em componentes reutilizáveis, e o navegador passou a rodar aplicações inteiras.

Hoje vivemos a fase em que a Inteligência Artificial participa da construção. Ela não substitui o raciocínio, mas acelera o trabalho repetitivo, sugere soluções, escreve trechos de código e conversa com as ferramentas que já usamos. É a quarta grande virada da web.

As quatro grandes viragens da web · você está vivendo a quarta

1.2 A evolução do design digital

O design seguiu um caminho parecido. No início, "fazer o layout" era trabalho de quem editava imagens no Photoshop e entregava um PNG para o programador recriar. Não havia interatividade, nem colaboração em tempo real, nem ideia de sistema.

Ferramentas como Sketch trouxeram o design vetorial focado em interface. Mas foi o Figma, rodando no navegador e permitindo que várias pessoas editem o mesmo arquivo ao vivo, que mudou a cultura de trabalho. O design virou colaborativo, versionado e baseado em componentes — exatamente como o código.

Hoje, design e desenvolvimento falam a mesma língua: tokens, componentes, estados, variantes. E a IA passou a conseguir ler esse design estruturado e transformá-lo em documentação, em código e em decisões — desde que o designer tenha organizado tudo com método.

Curiosidade

O Figma foi lançado publicamente em 2016, mas levou anos para convencer o mercado de que um editor de design "dentro do navegador" poderia substituir programas pesados de desktop. A aposta na colaboração em tempo real foi o que virou o jogo — a mesma lógica que torna o Figma o ponto de encontro perfeito entre design e IA hoje.

1.3 Como a IA mudou o mercado

A mudança mais importante não é técnica, é de papel. Quando uma ferramenta consegue gerar um rascunho de tela, escrever o CSS de um componente ou redigir a documentação de um fluxo, o trabalho braçal perde valor — e o trabalho de decisão ganha.

O mercado deixou de pagar bem por "saber operar o software". Passou a valorizar quem sabe fazer as perguntas certas, definir o problema, julgar a qualidade do que a IA produz e costurar tudo dentro de um objetivo de negócio. A IA é rápida; ela só não sabe o que é importante. Isso ainda é com você.

Atenção

Usar IA não é terceirizar o pensamento. Quem entrega o que a ferramenta cuspiu sem revisar, sem entender e sem critério, produz trabalho medíocre — só que mais rápido. O profissional valioso é o que usa a IA para ir mais longe, não para pensar menos.

1.4 O Web Designer como solucionador de problemas

Pare de pensar em "Web Designer" como "quem deixa as coisas bonitas". O profissional moderno é um arquiteto de experiências e um solucionador de problemas. Beleza é consequência de boas decisões — não o objetivo.

Na prática, isso significa transitar por três frentes ao mesmo tempo:

  • Problema — entender quem é a pessoa, o que ela precisa e qual obstáculo está no caminho.
  • Experiência — desenhar o caminho mais claro, agradável e eficiente até a solução.
  • Execução — construir (ou orientar a construção) com qualidade, usando design system, código e IA.

É essa visão de ponta a ponta que esta apostila vai te dar. E a IA entra justamente para liberar seu tempo das tarefas mecânicas, para que você possa investir energia onde ela realmente importa: nas decisões.

Conceito-chave

O profissional do futuro não compete com a IA — ele conduz a IA. Seu diferencial é o critério: saber o que pedir, reconhecer o que presta e tomar a decisão final. Ferramenta nenhuma substitui isso.

Módulo 02 · Fundamentos

Fundamentos de UX e UI

Antes de abrir o Figma, você precisa entender o que torna um produto bom de usar. UX e UI são as duas metades disso — e confundi-las é o erro número um de quem está começando.

2.1 A diferença entre UX e UI

UX (User Experience) é a experiência completa de usar algo: o quanto é fácil, rápido, agradável e útil. É invisível quando funciona — você só percebe a UX quando ela é ruim. UI (User Interface) é a camada visível: cores, botões, tipografia, espaçamentos, ícones. É a parte com que a pessoa interage diretamente.

A analogia clássica: numa casa, a UX é a planta arquitetônica — onde ficam os cômodos, se a circulação faz sentido, se a cozinha está perto da sala. A UI é o acabamento — a cor das paredes, o estilo dos móveis, a textura do piso. Uma casa linda com planta péssima é desconfortável de morar. Uma planta perfeita sem acabamento nenhum é fria. Você precisa das duas.

UX e UI se sobrepõem, mas não são a mesma coisa · um produto excelente precisa das duas
Conceito-chave

Resumo de bolso: UX é a decisão, UI é a aparência. UX pergunta "isso faz sentido para a pessoa?". UI pergunta "isso está claro e bonito na tela?". Bom designer pensa nas duas — nunca pula direto para a cor do botão.

2.2 Usabilidade

Usabilidade mede o quão fácil é alcançar um objetivo usando o produto. Um sistema usável é aquele em que a pessoa consegue fazer o que veio fazer sem precisar pensar demais. O livro que melhor resume isso tem um título perfeito: "Não me faça pensar".

Usabilidade tem pilares mensuráveis:

  • Eficiência — quão rápido a pessoa conclui a tarefa.
  • Facilidade de aprendizado — quão rápido um novato entende como usar.
  • Memorabilidade — se a pessoa volta depois de um tempo, ainda lembra como funciona?
  • Prevenção de erros — o sistema evita que a pessoa erre, e ajuda a se recuperar quando erra.
  • Satisfação — no fim, foi agradável usar?

2.3 As 10 Heurísticas de Nielsen

Em 1994, Jakob Nielsen publicou dez princípios gerais para o design de interfaces. Trinta anos depois, eles continuam sendo a régua mais usada do mundo para avaliar usabilidade. Decore esta tabela — ela vai te acompanhar pela carreira inteira.

#HeurísticaO que significa na prática
1Visibilidade do statusO sistema sempre mostra o que está acontecendo (carregando, salvo, enviado).
2Linguagem do usuárioFalar a língua de quem usa, não jargão técnico do sistema.
3Controle e liberdadePermitir desfazer, voltar e sair — a famosa "saída de emergência".
4Consistência e padrõesO mesmo elemento se comporta igual em todo lugar do produto.
5Prevenção de errosMelhor impedir o erro do que só mostrar uma mensagem depois.
6Reconhecer > lembrarMostrar as opções na tela em vez de exigir que a pessoa decore.
7Flexibilidade e eficiênciaAtalhos para experts, caminho simples para iniciantes.
8Design minimalistaMostrar só o necessário; cada elemento extra compete por atenção.
9Ajuda a se recuperarMensagens de erro claras, em linguagem humana, com a solução.
10Ajuda e documentaçãoQuando necessária, deve ser fácil de achar e objetiva.
Exemplo real · Heurística aplicada

Pense num formulário de cadastro. A heurística nº 5 (prevenção de erros) aparece quando o campo de e-mail avisa "faltou o @" antes de você enviar, em vez de recarregar a página e perder tudo. A nº 1 (visibilidade) aparece no botão que vira "Enviando..." ao ser clicado, para você saber que algo está acontecendo.

Reparou? Boas decisões de UX são quase invisíveis — você só sente falta quando elas não existem.

2.4 Acessibilidade e Design Inclusivo

Acessibilidade é garantir que pessoas com deficiência consigam usar seu produto: quem enxerga pouco, quem não enxerga, quem não ouve, quem tem dificuldade motora ou cognitiva. Design Inclusivo vai além — projeta pensando na maior diversidade de pessoas e situações desde o começo.

Não é favor nem "extra bonito de fazer". É responsabilidade profissional — e, no Brasil, muitas vezes é exigência legal. Além disso, soluções acessíveis costumam ser melhores para todo mundo: legendas ajudam quem é surdo e também quem está no ônibus sem fone; bom contraste ajuda quem tem baixa visão e também quem usa o celular no sol.

  • Contraste — texto precisa de contraste suficiente com o fundo (a régra WCAG pede no mínimo 4.5:1 para texto normal).
  • Tamanho de toque — botões grandes o bastante para o dedo (mín. ~44px).
  • Texto alternativo — imagens descritas para quem usa leitor de tela.
  • Navegação por teclado — dá para usar tudo sem mouse.
  • Não depender só de cor — um erro não pode ser indicado apenas por "ficar vermelho".
Curiosidade

O conceito de Modo Calmo que você pode ativar no rodapé deste menu é um exemplo de design inclusivo: reduz brilhos e animações para pessoas sensíveis a estímulos visuais — algo valioso, por exemplo, para parte das pessoas autistas. Acessibilidade não é só rampa de cadeira de rodas; é pensar em todos os tipos de mente e corpo.

Módulo 03 · Fundamentos

Dominando o Figma

O Figma é onde a maior parte do design digital do mundo acontece hoje. Este módulo te dá o domínio dos conceitos que separam quem "mexe no Figma" de quem realmente projeta com método — e que tornam seu trabalho legível para a IA.

3.1 O que é o Figma e como ele se organiza

O Figma é uma ferramenta de design de interfaces que roda no navegador, permite colaboração em tempo real e organiza o trabalho em arquivos, páginas e frames. Tudo é vetorial (escala sem perder qualidade) e tudo pode ser transformado em componente reutilizável.

A interface tem quatro regiões que você precisa reconhecer de olhos fechados:

As quatro regiões da interface · ferramentas · camadas · canvas · propriedades

3.2 Frames e Constraints

O Frame é o contêiner fundamental do Figma — pense nele como uma "tela" ou uma "caixa" que guarda outros elementos. Toda tela de app, todo card, todo botão geralmente vive dentro de um frame. Frames podem conter outros frames, criando hierarquia.

As Constraints (restrições) definem como um elemento se comporta quando o frame que o contém muda de tamanho. Você diz: "esse botão fica grudado embaixo", "essa logo fica centralizada", "esse texto estica junto com a largura". É o primeiro passo rumo ao design responsivo — telas que se adaptam ao celular e ao desktop, exatamente como esta apostila faz.

Curiosidade

Constraints resolvem o "redimensionar", mas têm limite: elas não reorganizam elementos quando o espaço muda muito. Para isso existe o Auto Layout — o recurso mais importante do Figma moderno, que veremos a seguir.

3.3 Auto Layout — o recurso que muda tudo

O Auto Layout faz com que um frame organize seus elementos automaticamente, como se fosse o flexbox do CSS. Você define a direção (horizontal ou vertical), o espaçamento entre os itens e o respiro interno (padding) — e o Figma cuida do resto. Adicionou um item? Ele entra na fila. Removeu? Os outros se reajustam.

Por que isso é revolucionário? Porque o design passa a se comportar como código de verdade. Um botão com Auto Layout cresce junto com o texto dentro dele. Uma lista com Auto Layout reposiciona tudo quando você adiciona um item. E — crucial para esta apostila — um design feito com Auto Layout é muito mais fácil de a IA traduzir em código, porque a estrutura espelha o jeito que o navegador realmente funciona.

conceito · Auto Layout ≈ Flexbox
/* O que você configura no Figma... */
Auto Layout: Vertical
Espaçamento entre itens: 16px
Padding: 24px
Alinhamento: Centralizado

/* ...vira praticamente isto em CSS */
.container {
  display: flex;
  flex-direction: column;
  gap: 16px;
  padding: 24px;
  align-items: center;
}
Dica de ouro

Regra de mestre: use Auto Layout em quase tudo. Quanto mais seu design imita a lógica do flexbox, mais previsível ele fica, mais fácil de manter, e melhor a IA consegue convertê-lo em código limpo. Designs "soltos", com tudo posicionado na mão, são frágeis e difíceis de traduzir.

3.4 Componentes e Variantes

Um Componente é um elemento que você cria uma vez e reutiliza em todo o projeto. Ao editar o componente "mestre" (o main component), todas as cópias (as instâncias) mudam junto. Pense num botão: você cria o componente "Botão" uma vez; se amanhã o cliente quiser todos os botões mais arredondados, você muda em um só lugar.

As Variantes agrupam versões diferentes do mesmo componente sob um único nome. O botão pode ter variantes: primário / secundário, normal / hover / desabilitado, com ícone / sem ícone. Em vez de cinco componentes soltos, você tem um "Botão" inteligente com propriedades que você liga e desliga.

Componentes e variantes são a fundação de um Design System — o tema do próximo módulo. E não por acaso: quando a IA lê um arquivo do Figma bem componentizado, ela enxerga um sistema organizado, e não um amontoado de retângulos.

3.5 Variáveis, Bibliotecas e Prototipação

As Variáveis guardam valores reutilizáveis — uma cor, um espaçamento, um texto — sob um nome. Em vez de usar o código de cor #FF2D9B espalhado por 200 lugares, você cria a variável cor/primária e a aplica. Mudou a marca? Troca o valor da variável e tudo se atualiza. Essas variáveis são a versão Figma dos Design Tokens que você vai dominar no Módulo 4.

As Bibliotecas publicam seus componentes e variáveis para serem usados em outros arquivos e por toda a equipe — é como um repositório compartilhado de peças de design.

Por fim, a Prototipação conecta as telas com interações: clicar num botão leva para outra tela, abrir um menu, mostrar uma animação. É como você transforma telas estáticas em um fluxo navegável que pode ser testado com pessoas reais — antes de escrever uma linha de código.

Frame

A caixa que contém tudo. Telas, cards, botões — todos vivem em frames.

Auto Layout

O flexbox do Figma. Organiza elementos automaticamente. Use em tudo.

Componente

Cria uma vez, reusa em todo lugar. Edita o mestre, muda todas as cópias.

Variável

Guarda cores, espaços e textos sob um nome. A base dos Design Tokens.

Design System Profissional

Um Design System é o que transforma telas bonitas em um produto consistente e escalável. Aqui você aprende a pensar como as grandes empresas: em tokens, componentes e regras — não em pixels soltos. E descobre por que um DS bem feito é o melhor amigo da IA.

A ideia central

Design System = linguagem visual + biblioteca de peças + regras de uso. Não é só um arquivo do Figma: é um acordo sobre como o produto se parece e se comporta, que vale para designers, devs e para a IA que gera código.

4.1 Tokens: a menor unidade do design

Um token é um valor de design guardado sob um nome semântico. Em vez de escrever #FF2D9B em 80 lugares, você cria --color-primary e usa o nome. Mudou a marca? Troca em um lugar só. É exatamente o conceito de Variáveis do Figma que vimos no Módulo 3 — e o mesmo de :root no CSS.

tokens.css
/* O mesmo token, do Figma ao código */
:root {
  --color-primary: #FF2D9B;   /* cor da marca */
  --space-md: 16px;        /* base do grid 8pt */
  --radius-card: 14px;      /* cantos dos cards */
  --font-display: "Space Grotesk";
}

Módulo 07 · Inteligência Artificial

Introdução ao Claude

Claude é o assistente de IA da Anthropic — e um parceiro de trabalho excepcional para quem desenha e desenvolve. Neste módulo você entende como ele "pensa", o que é a janela de contexto e como usar Projetos e Artefatos para produzir de verdade.

7.1 O que é Claude e como ele funciona

Claude é um modelo de linguagem: foi treinado em uma quantidade enorme de texto e aprendeu a prever e gerar linguagem de forma coerente. Na prática, ele lê o que você escreve (o prompt) e responde com texto, código, análises ou ideias. Não é um buscador: é um raciocinador que trabalha com a informação que você fornece.

Para um web designer, isso significa um colega disponível 24h que escreve código, revisa acessibilidade, gera documentação, cria personas, estrutura Design Systems e converte layout em HTML/CSS — desde que você saiba conversar com ele.

7.2 A Janela de Contexto (Context Window)

A janela de contexto é a "memória de trabalho" do Claude dentro de uma conversa: tudo que você enviou e tudo que ele respondeu. É enorme, mas não infinita. Entender isso muda como você trabalha:

Analogia da mesa de trabalho

Imagine uma mesa grande: cabe muita coisa, mas se você empilhar arquivos demais, os primeiros somem embaixo da pilha. Dê ao Claude o contexto certo — nem de menos (ele adivinha), nem informação irrelevante demais (ele se dispersa).

7.3 Projetos e Artefatos

Em Projetos, você guarda instruções e arquivos que valem para todas as conversas daquele tema — ideal para manter o contexto da sua marca ou do seu produto sempre à mão. Já os Artefatos são janelas onde o Claude constrói algo navegável e editável ao lado da conversa: uma página HTML, um componente React, um diagrama. Esta própria apostila é um artefato.

  • Diferenças práticas entre Claude e outras IAs

  • Projetos: contexto persistente para seu trabalho
  • Artefatos: construindo e iterando ao vivo
  • Casos de uso reais para designers e devs

8.2 Cadeia de raciocínio e estruturas reutilizáveis

Pedir à IA para "pensar passo a passo" antes de responder melhora muito tarefas complexas. E quando um prompt funciona bem, transforme-o em template: troque só as variáveis (produto, público, tom) e reutilize. É assim que se cria velocidade sem perder qualidade.

8.3 Biblioteca de prompts — como usar

A seguir, 120 prompts prontos, divididos em seis áreas. Cada um é um ponto de partida testável: copie, substitua os trechos em [colchetes] pelo seu contexto e refine a resposta com um segundo pedido. Eles seguem a anatomia do tópico 8.1 — quando precisar de mais qualidade, adicione contexto e defina o formato de saída.

Regra de ouro

Prompt bom não é prompt longo — é prompt claro. Diga quem é a IA naquele momento ("atue como pesquisador de UX"), o que você quer, em que formato, e o que evitar. Depois itere.

8.4 20 prompts de UX — pesquisa, personas e estratégia

    Atue como pesquisador(a) de UX. Com base nestas anotações de entrevista: [colar], crie uma persona completa com nome fictício, idade, ocupação, objetivos, frustrações, comportamentos digitais e uma citação que a represente. Formato: ficha em tópicos.

    Recebi estas respostas de pesquisa: [colar]. Sintetize em 5 a 7 insights acionáveis, agrupando por padrão recorrente. Para cada insight, indique quantas pessoas mencionaram algo relacionado.

  12. Heurísticas

  13. User flow

  14. Métricas

    Para o objetivo de negócio "[ex. aumentar matrículas]", sugira 5 métricas de UX que indicariam progresso (ex. taxa de conclusão, tempo até a primeira ação) e como medir cada uma.

  15. JTBD

    Reescreva estas funcionalidades como Jobs To Be Done: [listar]. Use o formato "Quando [situação], quero [motivação], para [resultado esperado]."

  16. Stakeholders

    Liste os stakeholders típicos de um projeto de [tipo]. Para cada um: interesse no produto, nível de influência e o que precisam ouvir de mim.

  17. Feedback

    Recebi estes comentários de usuários: [colar]. Categorize em elogios, reclamações, pedidos de feature e bugs. Para cada categoria, destaque os 3 temas mais frequentes.

  18. Contexto adverso

    Para a persona [descrição], liste 5 contextos de uso adversos (ex. sol forte, internet lenta, uma mão ocupada) e como cada um deve influenciar decisões de UX.

  19. Storytelling

    Transforme estes insights de pesquisa [colar] numa narrativa curta para a liderança: comece pelo problema do usuário, mostre a evidência e termine com a oportunidade. Máx. 150 palavras.

  20. Critérios UX

    Para a funcionalidade "[descrever]", escreva critérios de aceitação focados na experiência, no formato Dado/Quando/Então, cobrindo o caminho feliz e 2 casos de borda.

Módulo 09 · Inteligência Artificial

MCP — Model Context Protocol

Este é o conceito que dá nome à apostila. O MCP é o padrão aberto que permite que uma IA como o Claude se conecte com segurança a ferramentas e dados externos — como o Figma, seu banco de dados ou seus arquivos. É a peça que transforma um assistente de texto em um colega que age.

9.1 O que é o MCP e o problema que ele resolve

O Model Context Protocol (MCP) é um padrão aberto criado pela Anthropic em novembro de 2024. Antes dele, cada conexão entre uma IA e uma ferramenta externa era uma gambiarra sob medida: um conector para o Figma, outro totalmente diferente para o Google Drive, outro para cada API. Não escalava.

O MCP resolve isso definindo uma única forma padronizada de a IA descobrir e usar ferramentas. Escreveu um servidor MCP uma vez? Qualquer IA compatível consegue usá-lo.

A analogia do USB-C

Pense no MCP como o "USB-C da inteligência artificial". Antes do USB-C, cada aparelho tinha um cabo diferente. O USB-C criou um conector universal. O MCP faz o mesmo para IA: um padrão único para conectar qualquer modelo a qualquer ferramenta ou fonte de dados.

9.2 A arquitetura: Host, Client e Server

O MCP tem três papéis. Entender essa divisão é o coração do módulo:

Figura 9.1 — O Host (app de IA) contém um Client que fala MCP com vários Servers, cada um expondo uma ferramenta ou fonte de dados.

9.3 O que um servidor expõe: Resources, Tools e Prompts

Cada servidor MCP pode oferecer três tipos de coisa: Resources (dados para ler, como um arquivo ou um design), Tools (ações que a IA pode executar, como "gerar código deste frame") e Prompts (modelos de interação pré-definidos pelo servidor). É essa tríade que o Claude descobre automaticamente ao se conectar.

A Glossário essencial

Termos técnicos e de front-end

  • Frame — a "caixa" que contém elementos no Figma; equivale a um contêiner.
  • Constraints — regras de como um elemento se comporta quando o frame é redimensionado.
  • Auto Layout — recurso do Figma que organiza elementos automaticamente; equivale ao flexbox.
  • Design Token — valor de design (cor, espaço, fonte) guardado sob um nome reutilizável.
  • Componente — elemento mestre reutilizável; editá-lo atualiza todas as cópias.
  • Variante — versão de um componente (ex.: botão primário, secundário, desabilitado).
  • Boilerplate — código inicial padrão que serve de ponto de partida.

Termos de Inteligência Artificial

  • Prompt — a instrução que você dá à IA.
  • Modelo de linguagem — IA treinada para entender e gerar texto (como o Claude).
  • Janela de contexto — a "memória de trabalho" da IA dentro de uma conversa.
  • MCP — Model Context Protocol; padrão aberto que conecta a IA a ferramentas e dados.
  • Host / Client / Server — os três papéis da arquitetura MCP.
  • Artefato — entregável navegável que o Claude constrói ao lado da conversa.
  • Code Connect — recurso que liga componentes do Figma aos componentes de código reais.

Termos de UX, UI e Design System

  • UX — Experiência do Usuário; como é usar o produto (a jornada).
  • UI — Interface do Usuário; a camada visual e interativa.
  • Usabilidade — o quão fácil e eficiente é usar algo.
  • Heurísticas de Nielsen — 10 princípios clássicos de usabilidade.
  • Persona — personagem que representa um grupo de usuários reais.
  • Wireframe — rascunho estrutural de uma tela, sem estética final.
  • Atomic Design — método que organiza a UI em átomos, moléculas, organismos, templates e páginas.
  • Design System — linguagem visual + biblioteca de componentes + regras de uso.
